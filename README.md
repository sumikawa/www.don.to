# 画像URLカタログ

`scripts/gen_image.rb` は `data/site.yml` の `cacherootdir` を走査し、Dropbox の共有リンクを
`data/image/YYYY.yml` に追加します。既存のURLは維持し、登録済みファイルはスキップします。
動画・音声も従来と同じカタログに登録します。年別YAMLは走査中に再利用し、保存時には
最新内容を読み直して統合します。走査開始・対象件数・API問い合わせ・再試行待ち・完了を表示します。

```sh
# リポジトリのルートから実行
bundle exec ruby scripts/gen_image.rb                 # 全年
bundle exec ruby scripts/gen_image.rb 2026            # 指定年
bundle exec ruby scripts/gen_image.rb 2026/0909-test  # 指定記事
```

`make -C data year` は `data/year.yml` の年、`make -C data` は全年を対象にします。
認証情報は `~/.env` のみ読み込み、既存の環境変数は上書きしません。
`DROPBOX_APP_KEY`、`DROPBOX_APP_SECRET`、`DROPBOX_REFRESH_TOKEN` が必要です。

ローカルで `gen_index` が記事の `.html.md.erb` を書き終えると、対象記事の登録を
別プロセスで開始します。ログは `logs/gen_image.log` に出力します。
Dropbox へのアップロード未完了、通信障害、APIの一時エラーでは30秒間隔で最大61回
（待機時間は合計30分、別途API応答時間）確認します。記事生成はこの待機をブロックしません。
認証・権限エラーは終了します。

HTTPS接続は問い合わせ間で再利用し、通信障害時は接続を破棄して次の試行で再接続します。
同じキャッシュ・出力先・対象指定で既に処理中の場合、後続の実行はスキップします。
全年・年指定・記事指定のように対象指定が異なる処理間では、この重複防止は働きません。

取得したURLは30件単位、および再試行待ちの前・終了時（例外やCtrl-Cを含む）にまとめて保存します。
年別ファイルをロックして最新データと統合し、アトミックに置き換えます。
強制終了や電源断で未保存分が失われた場合も、再実行で共有リンクを再取得できます。
待機上限を超えたファイルは未登録のまま残り、同期完了後に上のコマンドを再実行すると
未登録分だけ再開できます。プロセス終了やMac再起動後も同様です。

RSpecではアップロード遅延、再実行、既存情報の保持、記事保存後の起動に加え、
接続の再利用・再接続、重複実行の抑止、まとめ書き、例外時の保存を検証しています。
2026年9月9日、実際の `make year` で未登録3件の共有リンク取得と年別YAMLへの保存を確認しました。
Dropboxへのアップロード遅延を伴う再試行はモックテストでの検証です。
